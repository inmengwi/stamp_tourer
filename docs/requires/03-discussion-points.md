# 논의 사항 및 결정 필요 항목

## 1. 플랫폼 선택

### 질문
타겟 플랫폼을 어떻게 할 것인가?

### 선택지

| 옵션 | 장점 | 단점 |
|------|------|------|
| **모바일 네이티브** (iOS + Android) | 최고 성능, 네이티브 기능 활용 | 개발 비용 높음, 2개 코드베이스 |
| **크로스 플랫폼** (React Native, Flutter) | 단일 코드베이스, 비용 절감 | 네이티브 대비 성능 저하 |
| **웹앱** (PWA) | 설치 불필요, 접근성 높음 | 오프라인 제한, 푸시 제한 |
| **웹 + 모바일** | 최대 커버리지 | 개발/유지보수 비용 최대 |

## 2. 스탬프 투어 데이터 확보

### 질문
스탬프 투어 정보를 어떻게 수집/관리할 것인가?

### 선택지

| 옵션 | 장점 | 단점 |
|------|------|------|
| **직접 수집** | 정확한 정보, 품질 통제 | 초기 비용 높음, 확장 어려움 |
| **사용자 제보** | 빠른 확장, 비용 절감 | 정보 신뢰도 문제 |
| **공공 API 연동** | 신뢰성 높음, 자동 업데이트 | 제공 데이터 제한적 |
| **업체 파트너십** | 공식 정보, 협력 가능 | 협상 필요, 시간 소요 |
| **하이브리드** | 장점 조합 | 복잡한 관리 |

### 고려사항
- 초기 데이터는 어떻게 확보?
- 데이터 검증 프로세스 필요?
- 저작권/라이선스 이슈는?

## 4. 수익 모델

### 질문
앱의 수익 모델을 어떻게 설정할 것인가?

### 선택지

| 옵션 | 설명 | 장단점 |
|------|------|--------|
| **완전 무료** | 모든 기능 무료 | 사용자 확보 용이, 수익 없음 |
| **프리미엄 (구독)** | 기본 무료 + 프리미엄 기능 유료 | 안정적 수익, 무료 사용자 이탈 가능 |
| **광고 기반** | 무료 + 광고 노출 | 사용자 경험 저하 |
| **투어 업체 제휴** | B2B 수익 모델 | 사용자 무료, 파트너 확보 필요 |
| **인앱 구매** | 특별 아이템/뱃지 판매 | 부분 수익, 과금 거부감 |

### 프리미엄 기능 후보
- 광고 제거
- 고급 통계/분석
- 경로 최적화 기능
- 무제한 그룹 생성
- 특별 뱃지/테마

## 5. MVP (최소 기능 제품) 범위
